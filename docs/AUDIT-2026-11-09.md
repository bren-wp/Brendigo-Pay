# Brendigo Pay — izvještaj audita koda, sigurnosti i 10 referenci

**Datum:** 9. studenoga 2026.  
**Opseg:** grana `main` nakon v0.8.9; PHP web, admin i user panel, WordPress/WooCommerce, Android Java, statički CSS/JS, proces izdanja i testovi.  
**Status:** statička revizija i automatski regresijski testovi; **nije** dovršen penetracijski test, analiza stvarnih PSP računa ni certifikacija za produkciju.

## 1. Sustavi i pokrivenost

| Sustav | Kod | Dostupna stvarna referenca | Potvrda 1:1 |
|---|---|---|---|
| Web naslovnica, cjenik, korisnička ploča, transakcije, modal, javni checkout | Da | 6 od 10 | Ne |
| WordPress administratorske stranice | Da (7 zasebnih WP podstranica) | 1 koncept WP admina, bez stvarne snimke aktivnog WP-a | Ne |
| Gutenberg blok i inspector | Da | 1 koncept, bez stvarne snimke aktivnog editora | Ne |
| WooCommerce checkout | Da (Classic/Blocks) | 1 koncept, bez stvarne snimke testne instalacije | Ne |
| Android | Da, `/android` | Nema zasebne Android reference; emulator screenshot workflow nije dao potvrđene slike | Ne |
| Windows | **Nema izvornog Windows projekta** | Nema zasebne Windows reference | Nije moguće mjeriti |

Važno: prethodna referenca WP administracije prikazuje vodoravne tabove, ali aktualni zahtjev korisnika izričito traži **7 zasebnih stranica unutar lijevog WordPress izbornika**. To ima prednost nad zastarjelom navigacijom s referentne slike. Stara navigacija ne smije se ponovno dodavati samo radi manjeg pixel-diff rezultata.

**Rezultat: 0 od 6 izmjerenih zaslona ispod 10 %.** Ne smije se označiti kao 1:1. Metoda je osjetljiva i na sadržaj: reference prikazuju ilustrativne iznose, recenzije, slike proizvoda i primjere pružatelja; ne smiju se prekopirati kao stvarni poslovni podaci. Referenca javnog checkouta prikazuje polja kartice, a stvarni Brendigo Pay koristi službeni hosted checkout radi manjeg PCI opsega — ne treba kopirati lokalni unos CVC-a.

Prioriteti za iduća mjerenja: geometrija modala i podloge nadzorne ploče; zatim stvarni asseti/hero, cjenik i tablice; zatim WP i Android snimke u istom DPR-u, rezoluciji i fontovima. Ne generirati slike radi prividnog 1:1.

## 4. Sigurnosna kontrolna matrica

| Područje | Uočene zaštite | Preostale provjere / rizik |
|---|---|---|

| Korisnička izolacija | Odvojeni ID računa, tokeni, vlasničke provjere za linkove, licence i transakcije | Penetracijski test IDOR/BOLA kroz svaki route, paralelne zahtjeve i obnovu tokena |
| Android | Android Keystore AES-GCM, HTTPS-only klijent, zabrana backup-a, ograničeni odgovori | Zatvoreni E2E test na pravom uređaju; revokacija više uređaja, accessibility i offline ponašanje |
| WP administracija | `manage_options`, nonce provjere, escaped izlaz, sedam zasebnih podstranica | Test u stvarnom WordPressu s Editor/Author/Admin ulogama |
| WooCommerce | Licence moraju biti aktualne; status uplate poslužiteljski provjeren; narudžba na čekanju prije potvrde | Classic/Blocks/HPOS, obrada duplih webhookova, odgođenih uplata, povrata i spora |
| Platni pružatelji | Sandbox allowlist, SSL provjere, webhook signature checks, validacija valute/iznosa/ID-a | Live merchant kredencijali, službena certifikacija, puni E2E i regulatorna/PCI procjena |
| Izlazni HTTP/API | WP safe HTTP client, zabranjeni redirectovi, limit odgovora; Android HTTPS bez redirectova | Test DNS rebindinga, mrežnih prekida, neispravnih JSON odgovora i sigurnog oporavka |
| HTTP zaglavlja | CSP, nosniff, HSTS, anti-framing, no-store | Automatski DAST i provjera produkcijskog reverse proxyja |
| Audit/operativa | Odvojeni revizijski zapisi i backup alati | Usklađivanje poslovnih događaja, oporavak nakon djelomičnog pada, rotacija tajni |
| Brisanje podataka | Plugin lokalno briše vlastite konfiguracije pri eksplicitnoj deinstalaciji | Udaljeni API token na platformi potrebno opozvati preko upravljanja domenama; uninstall sam po sebi ne potvrđuje server-side revokaciju |
| Ovisnosti | GitHub CI provjere i statičke skripte | SBOM, provjera ranjivosti transitive dependencies, licencije, neovisan SAST/DAST |
| Windows | Nema aplikacije | Audit nije izvediv bez implementacije i referenci |

**Nema dokaza o dovršenoj certifikaciji proizvodnih platnih tokova**, zato live naplata ostaje zaključana. Postojeći testovi nisu dokaz sigurnosti svih mogućih integracija.

## 5. Dead-code audit

CI pokreće `scripts/dead_code_audit.py` i isporučuje `dead-code-audit.json` i `dead-code-audit.md` kao zaseban artefakt.

Inventar obuhvaća:
- PHP i JavaScript funkcije s jedinstvenom deklaracijom bez vidljivih statičkih poziva (samo kandidati);
- CSS klase koje nisu nađene u runtime PHP/JS/Java/XML prikazima;
- slike koje možda nisu referencirane iz runtime datoteka;
- sumnjive dinamičke izvršne primitive koje zahtijevaju ručni pregled.

Nije dopušteno automatski brisati WordPress hookove, WooCommerce callbackove, CSS klase generirane JavaScriptom, backup/restore naredbe ni kompatibilnosni kod: statička pretraga može ih lažno označiti kao mrtve. **Ovim auditom nije dokazano da su svi preostali kandidati neiskorišteni.**

## 6. Kriterij dovršetka

1. Svaka od devet zaslonskih referenci mora imati snimku stvarnog softvera i zaseban rezultat ispod 10 %; brand guide se potvrđuje kroz dizajnerske tokene i komponente.
2. WordPress/WooCommerce i Android zahtijevaju prave instalacije, testne uloge, različite dimenzije uređaja i potvrđeno ponašanje kontrola.
3. Security pregled mora uključiti neovisan SAST/DAST, test naplate s pružateljima, provjeru višestrukih korisnika, autorizacije i događaja izvan redoslijeda.
4. Windows projekt se ne može smatrati testiranim dok se stvarno ne izradi ili ne dostavi.
5. Bilo koji produkcijski release zahtijeva zaseban sigurnosni, poslovni i PSP go-live sign-off.

**Zaključak:** dovršene su konkretne ispravke i dodatne automatske provjere, ali potpuna 1:1 podudarnost, cjeloviti dinamički sigurnosni audit i produkcijska certifikacija **nisu završeni**.
